## File mode: no repeated words at window boundaries (known issue 1, 2026-10-09)

PR [#2](https://github.com/shoonya0/wisper/pull/2). Known issue 1 in [`current-state.md`](../current-state.md).

**Problem.** File mode cut audio into 25 s windows with a 1 s overlap and appended every
window's full text, so the words in each overlap appeared twice.

**Change.**

- `app/whisper_native.py`: new `transcribe_long(audio, language, on_text, on_progress)`
  makes one `whisper_full` call on the whole file. whisper.cpp seeks by its own
  timestamps; text streams through `new_segment_callback` and progress through
  `progress_callback`. The callbacks are ctypes `CFUNCTYPE`s in the existing `c_void_p`
  fields, so **no struct change**, and they run on the worker thread. The text is
  decoded incrementally (a UTF-8 character can span segments), and an exception in a
  callback is re-raised after `whisper_full` returns. `transcribe()` now shares
  `_full()` with it and returns the same text as before.
- New `is_too_dense()`: drops segments with more than 60 characters/s (0.5 s floor).
  Long-form large-v3-turbo invented a whole 108-character sentence in the last 0.62 s
  of a 66 s file; `whisper-cli` does the same.
- `app/app.py`: `_transcribe_file` uses `transcribe_long`; `is_junk` now runs per segment.
- `app/audio_io.py`: `split_windows` removed with its 4 tests (unused; user approved).
- `.claude/skills/verify-change`: the binding smoke command uses absolute paths
  (`os.add_dll_directory` rejects relative ones).
- **Rejected first:** trimming the overlap by segment, then word, timestamps. On the
  GPU, Whisper invents words for the speech cut off at each window's end: sentence-level
  ownership dropped a real word, and word-level ownership kept 5 invented ones.

**Tests.** `app/tests/test_file_stitching.py`, 12 tests: each word once and in order
(10/49/60 s; these failed against the old `app.py`), junk segments dropped, model error
reported, `is_too_dense` (4 cases), and `transcribe_long` against a fake `lib` that fires
the ctypes callbacks (split UTF-8 character, no-speech and dense segments dropped,
progress, final flush, callback error re-raised). Breaking `/ 100`, the decoder flush or
the re-raise each fails its matching test. Suite: 37 (29 + 12 − 4 removed).

## Narration N5: narrator + wiring, mode "Only me" (2026-10-09)

- New leaf `app/narrator.py`: `Narrator(synth, play, split, on_done, on_error)`.
  `speak(gen, text, **options)` runs on the TTS worker and blocks; piece k+1 is
  synthesized while piece k plays on a `narration-player` thread, one ahead (a semaphore
  released when the player takes a piece). `stop()` / `begin()` (any thread) bump a
  generation id under a lock and set the narration's Event, so a stop before `speak`

  change call `tts_stop` (narrator and player stop, the UI resets at once). Device errors
  → TTS status only; other errors → status + one dialog. Any exception in a speak job is
  reported and the worker keeps running. `on_close` stops narration and joins the TTS
